# mantikai.com — план первой версии сайта

Сайт мобильного приложения Mantikai (AI-таро для iOS и Android): маркетинговая страница, юридические документы,
поддержка, форма обратной связи. Чистая статика, собирается SSG и публикуется на GitHub Pages.
Каждая задача ниже — самостоятельный промпт для кодинг-агента. Выполнять по порядку, по одной.

## Правила работы

- **Перед выполнением любой задачи — grill me.** Сначала расспроси владельца о неочевидных решениях
  (поведение, UX, тексты, крайние случаи), предложи свои варианты с рекомендацией; код — только после ответов.
  Принятые решения — в `docs/decisions.md`.
- **Каждая задача — в отдельной ветке** от свежего `main`: `feature/<номер>-<кратко>` (например,
  `feature/1.2-ssg-i18n`), исправления — `fix/<кратко>`. В `main` — только через PR после зелёного CI;
  в `main` напрямую не коммитим. История линейная: перед мёржем ветку ребейзим на свежий `main`
  (`git rebase main`, `git push --force-with-lease`), мёржим через «Rebase and merge», без merge-коммитов.
- **Nx — только через генераторы.** Приложения, библиотеки, компоненты, сервисы и прочие сущности Nx
  создаются консольными командами Nx (`yarn nx g @nx/angular:library …`, `yarn nx g @nx/angular:component …`
  и т. п.), а не руками: так корректно появляются `project.json`, пути в `tsconfig.base.json`, теги и таргеты.
  Перед запуском — `--dry-run`, чтобы проверить, что и куда будет создано.
- **Все библиотеки — в `libs/`** (например, `libs/ui`, `libs/content`, `libs/analytics`), приложения — в `apps/`.
  Импорт библиотек — только через алиас (`@mantikai/<имя>`), не относительными путями.
- Перед тем как считать задачу готовой: `nx lint`, `nx test`, `nx build`, `nx e2e` зелёные; статус — в
  `docs/progress.md`.
- Не расширяй объём задачи: то, что в плане помечено «Не входит», без явной просьбы не делаем.

## Зафиксированные решения

- **Репозиторий:** публичный `mantikai.com` на GitHub. Никаких секретов в репозитории; ID счётчиков, адрес и
  publishable-ключ Supabase публичны по своей природе и лежат в конфиге.
- **Стек:** Angular 22 в Nx-монорепе (`apps/site`, `apps/site-e2e`, библиотеки — в `libs/`), standalone, zoneless, `OnPush`,
  сигналы везде (`signal`, `computed`, `input()`, `output()`, `viewChild()`; без `@Input`/`@Output`/RxJS там,
  где хватает сигналов). Перед использованием API сверяться с актуальной документацией angular.dev и nx.dev.
- **Рендеринг:** SSG — `outputMode: "static"`, все серверные роуты `RenderMode.Prerender`. Гидрация включена.
- **Языки:** встроенный i18n Angular (`@angular/localize`, XLF). `en` — исходный, в корне (`subPath: ""`);
  `ru` → `/ru/`, `es` → `/es/`. Без автоперенаправления по языку браузера.
- **Пакетный менеджер:** Yarn 4 (Corepack, `nodeLinker: node-modules`), npm не используем.
- **Тесты:** Vitest через `@angular/build:unit-test` — юнит, Playwright (Chromium desktop + mobile) — e2e по
  собранной статике.
- **Браузеры:** сайт работает в старых браузерах (`.browserslistrc`: Chrome > 63, Firefox > 66, последние
  Safari/iOS и т. д.). Синтаксис понижает сборка, недостающие API — точечные модули `core-js/stable/*` в
  `polyfills` (`apps/site/project.json`). Предупреждение Angular о неподдерживаемых браузерах — ожидаемое.
- **Стили:** Tailwind CSS 3.4 (v4 не работает в старых браузерах: `@layer`, `@property`, `color-mix()`).
  Конфиг — `apps/site/tailwind.config.js` (Angular подхватывает сам), токены приложения — в `theme.extend`;
  глобальный `styles.scss`. Классы — в шаблонах и `host: { class: '…' }`. У компонентов нет своих файлов
  стилей. Прозрачность — модификаторами (`bg-gold/50`), утилиты `*-opacity-*` выключены.
- **Линт и формат:** ESLint (общий конфиг в корне, строгие правила — см. `docs/decisions.md`), Prettier
  (`printWidth: 140`).
- **Компоненты:** Angular CDK — только если понадобится сложное поведение (оверлей, фокус-ловушка, a11y).
- **Формы:** Angular Signal Forms для всех форм.
- **Дизайн:** как в приложении — тёмная тема, палитра и шрифты из приложения (ниже), знак `mark.svg`.
  Светлой темы нет.
- **Хостинг:** GitHub Pages, деплой из GitHub Actions. `mantikai.com` — основной домен. `mantikai.ru`,
  `mantika.ru` — 301 на `https://mantikai.com$request_uri` с сервера владельца (nginx).
- **Контакты:** везде `support@mantikai.com`.
- **Документы:** политика конфиденциальности, условия использования, согласие на обработку данных из формы.
  Тексты готовит владелец и кладёт в `content/`. Агент делает только механизм и файлы-заглушки со структурой.
  **Не писать и не генерировать юридические тексты, не добавлять в репозиторий персональные данные владельца
  и описания того, как готовились документы.**
- **Аналитика:** Google Analytics 4 и Яндекс Метрика — загружаются **только после согласия** в баннере
  внизу экрана. Вебвизор выключен.
- **Обратная связь:** форма → Edge Function `contact` в Supabase приложения → таблица + уведомление в Telegram.
  Функция делается в репозитории приложения (отдельный файл задач `app-tasks.md`).
- **Минимальный возраст пользователей:** 18+.
- **Не входит:** блог, светлая тема, автоперенаправление по языку, детальные категории cookies (только
  «Принять» / «Отклонить»), капча, свой сервер для сайта, отзывы и рейтинги из сторов.

## Этап 1. Каркас

**1.1. Рабочее пространство.** ✅ Выполнено (см. `docs/progress.md`, `docs/decisions.md`). Создай Nx-воркспейс с Angular-приложением `apps/site` и Playwright-проектом
`apps/site-e2e`: сборщик `@angular/build` (esbuild), юнит-тесты Vitest, ESLint + Prettier, standalone,
zoneless (без zone.js), строгий TypeScript и строгие шаблоны, `changeDetection: OnPush` по умолчанию в генераторах.
Подключи Tailwind 3.4 (глобальный `styles.scss`, без токенов — они в 2.1) и полифилы core-js. Создай `CLAUDE.md`
(что это за проект, команды; правила из раздела «Правила работы» этого плана — grill me перед задачей, Nx только
через генераторы, библиотеки в `libs/`; сигналы везде, классы Tailwind в шаблонах и `host`, без файлов стилей у
компонентов, Signal Forms для форм; отступления от плана — в `docs/decisions.md`) и `docs/progress.md`, `docs/decisions.md`; этот план — `docs/plan.md`.
Готово, когда `nx lint`, `nx test`, `nx build` проходят на пустом приложении.

**1.2. SSG и языки.** Настрой `@angular/localize`: `sourceLocale: "en"` с `subPath: ""`, локали `ru`, `es`
(файлы `apps/site/src/locale/messages.{ru,es}.xlf`), `localize: true`, `outputMode: "static"`, серверные роуты
(`app.routes.server.ts`) — все `RenderMode.Prerender`. Роуты-заглушки: `''` (главная), `privacy`, `terms`,
`consent`, `support`, `delete-account`, `contact`, `404`, `**` → страница 404. На выходе:
`dist/.../browser/` — английская версия в корне, `ru/` и `es/` рядом, у каждой страницы `<route>/index.html`.
Пост-сборочный шаг (Nx-таргет): скопировать `404/index.html` английской версии в корень как `404.html`
(GitHub Pages отдаёт только его). `.nojekyll` и `CNAME` не нужны: деплой через Actions без Jekyll, домен — в настройках Pages. `<html lang>` у каждой
локали свой. Переключение языка — обычные `<a href>` на тот же путь в другой локали (это другая сборка,
полная загрузка страницы). Таргет `serve-static`: раздать собранную папку через `http-server` (он отдаёт
`404.html` как GitHub Pages) — по нему гоняется e2e. Первый e2e — контрактный: все шесть адресов приложения
(`/privacy`, `/terms`, `/ru/privacy`, `/ru/terms`, `/es/privacy`, `/es/terms`) отдают 200 и содержат `<h1>`;
главная каждой локали отдаёт 200 с правильным `lang`; несуществующий адрес отдаёт 404-страницу.

**1.3. CI и деплой.** ✅ Выполнено раньше 1.2 (`.github/workflows/ci.yml`): проверки на PR, деплой заглушки на push в `main`. GitHub Actions: на PR — `nx affected -t lint test build e2e` (Playwright с кэшем браузеров);
на push в `main` — полная сборка, e2e, затем `actions/upload-pages-artifact` + `actions/deploy-pages`
(окружение `github-pages`, права `pages: write`, `id-token: write`). Concurrency: отменять устаревший деплой.
Node — LTS, Yarn через Corepack (`corepack enable`), кэш Yarn и Nx. Готово, когда пустой сайт открывается на `mantikai.com`.

## Этап 2. Дизайн и оболочка

**2.1. Токены и типографика.** В `apps/site/tailwind.config.js` (`theme.extend`) — цвета, радиусы и шрифты из
таблицы выше (имена: `background`, `surface`, `gold`, … → классы `bg-surface`, `text-gold`; шрифты `display`,
`text` → `font-display`, `font-text`).
Шрифты — пакеты `@fontsource` (Cormorant Garamond: 500, 600, 700, 500-italic; Manrope variable или 400–700),
подмножества latin + cyrillic, `font-display: swap`, preload основного начертания. Базовые стили: фон
`background`, текст `text-primary` Manrope 500, заголовки Cormorant 700 с увеличенными размерами, ссылки
`gold`, видимый `:focus-visible` (базовые стили — в `@layer base` `styles.scss`). `@tailwindcss/typography`
(версия для Tailwind 3): тема `prose` под палитру (для юридических
текстов). Скопируй из приложения `assets/branding/mark.svg` → фавикон (SVG + PNG 32/180/192/512),
`site.webmanifest`, `theme-color`. Готово, когда есть страница-витрина `/_styleguide` (только в dev, не
пререндерится) с цветами, шрифтами, кнопками.

**2.2. Оболочка страниц.** Компоненты: шапка (знак + вордмарк «Mantikai», навигация: Возможности, Расклады,
Поддержка; справа — выбор языка; на мобильных навигация — в раскрывающемся меню с управлением с клавиатуры,
выбор языка остаётся в шапке). **Выбор языка** — выпадающий список: на кнопке флаг текущего языка и код
(`EN` / `RU` / `ES`), в списке — флаг и название языка на нём самом (English, Русский, Español), текущий
отмечен. Флаги: `en` — США, `ru` — Россия, `es` — Испания; SVG из пакета `flag-icons` (MIT), только три
нужных файла, не весь CSS пакета. Нативный `<select>` не подходит — в `<option>` нельзя показать картинку,
а эмодзи-флаги в Windows выводятся буквами. Делать на CDK Menu (`@angular/cdk/menu`): пункты — обычные
`<a href>` на тот же путь в другой локали (смена языка — переход на другую сборку с полной загрузкой);
клавиатура, `Esc`, фокус и `aria-*` — из CDK. Поисковикам языковые версии отдаёт `hreflang` в `<head>`,
не меню. Флаг декоративный (`alt=""`), подпись даёт текст.
Футер (Политика, Условия, Поддержка, Удаление аккаунта, «Настройки cookies» — пустой обработчик до 4.2,
`support@mantikai.com`, © год), подсказка о языке: если `navigator.language` совпадает с другой локалью
сайта — ненавязчивая плашка «Эта страница есть на русском» со ссылкой и крестиком (выбор помнится в
`localStorage`, обёрнут в try/catch; на сервере не рендерится). Сервис метаданных: `title`, `description`
(переводимые), `canonical`, `hreflang` для всех трёх локалей + `x-default` → en, Open Graph и Twitter Card.
Все строки интерфейса — через `i18n`/`$localize` с осмысленными ID; переводы ru и es — в XLF.

## Этап 3. Контент

**3.1. Юридические страницы.** Тексты в Markdown: `content/{en,ru,es}/{privacy,terms,consent}.md` с
frontmatter (`title`, `updated` — дата последней редакции). Nx-таргет `content` (запускается перед сборкой
через `dependsOn`): Node-скрипт на `marked` + `gray-matter` превращает их в TypeScript-модули
`generated/{page}.ts` с картой `{ en, ru, es } → { title, updated, html, toc }`; `generated/` в `.gitignore`.
Страницы `privacy`, `terms`, `consent` — один компонент: берёт текст по `LOCALE_ID`, выводит заголовок,
«Обновлено: <дата>» в формате локали, оглавление по `h2` с якорями, текст в `prose`. Роуты ленивые — тексты
не попадают в бандл главной. Если файла локали нет — английский текст и пометка «Документ доступен на
английском». **Тексты не писать:** создать заглушки только со структурой — заголовки разделов и строка
`TODO: текст предоставит владелец`. Разделы политики: оператор и контакты; какие данные и откуда (приложение:
вход Google/Apple, вопросы и толкования, письма в поддержку; сайт: cookies и аналитика, форма обратной связи);
цели; получатели (Supabase, провайдер LLM, Google Analytics, Яндекс Метрика, Telegram); хранение и удаление;
права пользователя; возраст 18+; изменения. Условия: сервис и его развлекательный характер; аккаунт;
лимиты; ограничение ответственности; возраст 18+; изменения; контакты. Согласие: что передаётся через форму
(имя, email, ник в Telegram, сообщение), зачем, срок, отзыв согласия. Тест: каждая страница каждой локали
рендерит заголовок и дату.

**3.2. Поддержка и удаление аккаунта.** `/support`: FAQ (раскрывающиеся пункты на `<details>`; вопросы:
что такое Mantikai, сколько раскладов в день и когда обновляется лимит — 1 карта дня и 3 расклада с вопросом
в сутки по UTC, как сменить язык и рубашку, почему нужен вход, где история, как удалить аккаунт, это
предсказание или развлечение), кнопки «Написать нам» (→ `/contact`) и `mailto:support@mantikai.com`.
`/delete-account` (страница для Google Play): как удалить в приложении — Настройки → Аккаунт → Удалить
аккаунт; что удаляется — аккаунт и все расклады сразу и безвозвратно; если доступа к приложению нет —
форма с темой «Удаление аккаунта» (`/contact?topic=account_deletion`) или письмо на support@ с адреса, через
который выполнялся вход. Тексты — через i18n.

**3.3. Маркетинговая главная.** Разделы: первый экран (заголовок, подзаголовок, бейджи сторов, скриншот в
рамке телефона, фон — тонкое звёздное небо как в знаке, без тяжёлых анимаций); «Как это работает» (задайте
вопрос → вытяните карты → получите толкование); три расклада (карта дня; три карты — прошлое / настоящее /
будущее; крест — суть → чего не делать → что делать → итог) со схемами раскладки в CSS/SVG; чем отличается
(толкование под ваш вопрос с позиционными значениями, классическая колода Райдера — Уэйта 1909 года,
выбор рубашки, три языка, история раскладов); галерея скриншотов (горизонтальная прокрутка со scroll-snap);
короткий FAQ со ссылкой на `/support`; финальный призыв с бейджами. Пометка «Приложение создано для
развлечения» — в футере главной. Скриншоты: `public/screenshots/{en,ru,es}/NN-name.webp`, список — в конфиге;
если для локали файла нет — берётся английский (владелец положит файлы позже, до тех пор — заглушки того же
размера). Изображения карт для оформления — несколько файлов из `assets/cards/` приложения (общественное
достояние). Бейджи сторов — официальные локализованные SVG (владелец скачает с сайтов Apple и Google и положит
в `public/badges/`). Конфиг `site.config.ts`: `appStoreUrl`, `googlePlayUrl` — пока `null`, тогда вместо бейджа
«Скоро в App Store / Google Play». Тексты пишет агент на английском; ru и es — переводы в XLF; все тексты
владелец вычитает. Lighthouse на мобильном: Performance и Accessibility ≥ 95; изображения с `width`/`height`,
`loading="lazy"` ниже первого экрана, `NgOptimizedImage`.

**4.1. Форма обратной связи** (после задачи A.2 в репозитории приложения). Страница `/contact`, Signal Forms
(`@angular/forms/signals`; если API в Angular 22 ещё experimental — всё равно используем, записать в
`decisions.md`). Поля: имя (обязательное, до 100), email (обязательное, формат), ник в Telegram (необязательный,
`^@?[A-Za-z0-9_]{5,32}$`), тема (вопрос / проблема в приложении / удаление аккаунта / другое; предзаполняется
из `?topic=`), сообщение (обязательное, 10–2000, счётчик символов), чекбокс согласия со ссылкой на `/consent`
(обязательный). Скрытое поле-ловушка `website` (вне экрана, `tabindex="-1"`, `autocomplete="off"`) и время
открытия формы. Ошибки — под полями после первого касания и при отправке, связаны через `aria-describedby`.
Отправка: `fetch` POST на `${supabaseUrl}/functions/v1/contact` (адрес и publishable-ключ — в
`site.config.ts`), тело `{ name, email, telegram, topic, message, locale, website, elapsedMs }`. Состояния:
отправка (кнопка заблокирована), успех (форма заменяется на «Спасибо, ответим на email»), ошибка 429 («Слишком
много сообщений, попробуйте позже»), прочие ошибки («Не отправилось — напишите на support@mantikai.com»).
e2e: валидация, успешная отправка и ошибки — с подменой запроса через `page.route`, без реального бэкенда.

**4.2. Cookies и аналитика.** Баннер внизу экрана: короткий текст со ссылкой на раздел о cookies в политике,
кнопки «Принять» и «Отклонить» одинаково заметные. Выбор — в `localStorage` (`mantikai.consent`:
`{ v: 1, analytics: boolean, at }`, try/catch); баннер не рендерится на сервере, показывается, пока выбора нет
или изменилась версия `v`. До согласия **ничего** не загружается — ни `gtag.js`, ни `tag.js` Метрики, ни
cookies. После «Принять» — динамически подключаются GA4 и Метрика (`webvisor: false`, `clickmap: true`,
`trackLinks: true`, `accurateTrackBounce: true`). «Настройки cookies» в футере снова открывают баннер; отзыв
согласия удаляет cookies `_ga*`, `_ym*` и перезагружает страницу. Просмотры при навигации роутера
отправляются вручную (`NavigationEnd`). События: клик по бейджу стора (`store_click` + платформа),
отправка формы (`contact_submit`). ID счётчиков — в `site.config.ts`; пустой ID — счётчик выключен (dev и
e2e). Сервис аналитики — один, с методами `pageView`, `event`; компоненты не знают о конкретных счётчиках.
e2e: до согласия нет запросов к `googletagmanager.com` и `mc.yandex.ru`; после «Принять» — есть (запросы
перехватываются и обрываются); после «Отклонить» — нет и после перезагрузки.
